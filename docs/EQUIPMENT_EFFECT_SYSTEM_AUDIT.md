# 裝備特效與詞綴觸發整理

本文件整理目前裝備 `specialEffects`、隨機詞綴 `affixBonuses`、強化詞條 `enhancementBonuses`、套裝效果與戰鬥核心的接線狀態。

目標不是只讓 tooltip 顯示漂亮，而是確保玩家看到的每一個特殊能力，都能在冒險、副本與後續塔戰鬥中以同一套規則觸發。

## 整體結論

目前裝備顯示系統與戰鬥核心已經改為共用解析方向。`EquipmentEffectResolver` 會統一讀取裝備基礎數值、`specialEffects`、`affixBonuses`、`enhancementBonuses`、`affixes[].stats`、套裝與戰術技能；冒險、副本與塔的主要戰鬥流程都已接入。

已相對穩定：

- 攻擊、防禦、生命、爆擊率、爆擊傷害、攻擊速度
- 吸血
- 穿甲
- 火焰額外傷害

已接上，但仍需要持續平衡與視覺打磨：

- 減傷、穿甲、吸血、火焰、冰、雷、毒
- 雙重打擊、處決、反傷、閃避、復活、生命恢復
- Boss 傷害、虛空傷害
- 金幣、經驗、掉落加成
- 套裝效果與戰術技能加成

剩餘風險：

- 數值平衡還需要實戰調整，尤其是復活、反傷、雙擊與獎勵加成。
- 特效已能顯示，但不同場景的表演強度仍可再細修。
- 新增裝備或詞條時必須跑 `scripts/EquipmentEffectCheck.mjs`，避免 tooltip 有寫但戰鬥沒觸發。

## 目前架構

目前共用解析層是 `src/js/managers/EquipmentEffectResolver.js`。

它負責把所有裝備來源整理成同一份效果總表：

- 裝備基礎數值
- `specialEffects`
- `affixBonuses`
- `enhancementBonuses`
- `affixes[].stats`
- 套裝效果
- 戰術技能

戰鬥核心與獎勵結算都不應該自己去猜 item 上面有哪些欄位。

## 觸發階段

### 1. 常駐數值

這類效果只要裝備上就應該立刻反映在角色面板與戰鬥。

| 效果 | 鍵值 | 現況 | 備註 |
|---|---|---|---|
| 攻擊 | `atk`, `attack` | 已接上 | 由 `CharacterLogic.getTotalAtk()` 統一計算 |
| 防禦 | `def`, `defense` | 已接上 | 由 `CharacterLogic.getTotalDef()` 統一計算 |
| 生命 | `hp` | 已接上 | `maxHp` 會吃 `getAffixHpBonus()` |
| 爆擊率 | `critChance` | 已接上 | 由 `getCritChance()` 計算 |
| 爆擊傷害 | `critDamage` | 已接上 | 由 `getCritDamage()` 計算 |
| 攻擊速度 | `attackSpeed` | 已接上 | 由 `getAttackSpeed()` 計算 |
| 全屬性 | `allStats` | 已接上 | 由共用解析器統一讀取 |

### 2. 攻擊命中時

這類效果在玩家攻擊命中後觸發。

| 效果 | 鍵值 | 現況 | 預期規則 |
|---|---|---|---|
| 吸血 | `lifesteal` | 已修正 | 造成傷害後，依傷害比例回血；早期低傷害至少回 1，滿血不觸發 |
| 火焰 | `fire` | 已接上 | 依比例追加傷害 |
| 冰 | `ice` | 已接上 | 命中後降低敵人攻擊頻率數秒 |
| 雷 | `thunder` | 已接上 | 命中後有機率讓敵人暈眩 |
| 毒 | `poison` | 已接上 | 命中後套用 DOT，會在戰鬥 tick 扣血與跳字 |
| 雙重打擊 | `double_strike` | 已接上 | 擲機率後追加副傷害 |
| 處決 | `execute` | 已接上 | 敵人低於血量門檻時追加傷害 |
| Boss 傷害 | `bossBonus` | 已接上 | 目標是 Boss 時提高玩家造成傷害 |
| 虛空傷害 | `voidDamage` | 已接上 | 作為額外特殊傷害加入攻擊 |
| 暈眩機率 | `stunChance` | 已接上 | 與雷屬性共用暈眩狀態流程 |
| 緩速機率 | `slowChance` | 已接上 | 與冰屬性共用緩速狀態流程 |

### 3. 玩家被攻擊時

這類效果在怪物攻擊玩家時觸發。

| 效果 | 鍵值 | 現況 | 預期規則 |
|---|---|---|---|
| 減傷 | `damageReduction` | 已接上 | 共用解析器會讀取 `specialEffects`、詞綴、強化與套裝來源 |
| 閃避 | `dodgeChance` | 已接上 | 擲機率成功時傷害歸零，場景顯示閃避 |
| 反傷 | `damage_reflect` | 已接上 | 受到傷害後，反彈部分實際傷害給怪物 |
| 復活 | `revive` | 已接上 | 死亡時擲機率，成功後回復部分生命 |

### 4. 戰鬥持續中

這類效果需要時間軸或戰鬥 tick。

| 效果 | 鍵值 | 現況 | 預期規則 |
|---|---|---|---|
| 生命恢復 | `hpRegen` | 已接上 | 戰鬥 tick 中每秒恢復生命 |
| DOT 中毒 | `poison` | 已接上 | 實際扣血、跳字、狀態圖示與倒數 |
| 緩速 / 暈眩 | `ice`, `thunder`, `slowChance`, `stunChance` | 已接上 | 會改變怪物攻擊排程或暫停攻擊 |

### 5. 戰鬥結算時

這類效果在戰鬥勝利、掉落與獎勵發放時觸發。

| 效果 | 鍵值 | 現況 | 預期規則 |
|---|---|---|---|
| 金幣加成 | `gold_bonus` | 已接上 | 戰鬥勝利時計算額外金幣 |
| 經驗加成 | `exp_bonus` | 已接上 | 戰鬥勝利時計算額外經驗 |
| 掉落加成 | `drop_bonus` | 已接上 | 掉落擲骰時增加機率 |

## 後續打磨順序建議

### 第一階段：數值平衡

先調整會破壞難度曲線的效果：復活、反傷、雙重打擊、處決、Boss 傷害、獎勵加成。

### 第二階段：視覺表演

讓裝備效果在戰鬥中更容易讀懂：雙擊、反傷、復活、DOT、回血、緩速、暈眩需要保有一致但不廉價的特效語言。

### 第三階段：新增裝備前驗收

任何新增裝備、詞綴、套裝或戰術技能後，都先跑 `scripts/EquipmentEffectCheck.mjs`，再進行手動遊玩驗收。

## 驗收標準

每個效果都需要至少有一個自動驗證案例。目前最低驗收腳本是：

```bash
node scripts/EquipmentEffectCheck.mjs
```

腳本會檢查：

- 裝備該效果
- 進行一次攻擊、受擊、戰鬥 tick 或結算
- 檢查 HP、傷害、狀態、獎勵是否符合預期

- 史萊姆之劍：命中後吸血
- 狼牙刀：雙重打擊會追加傷害
- 泰坦之錘：低血敵人受到處決加成
- 冰系武器：敵人攻擊頻率降低
- 雷系武器：敵人被暈眩
- 毒系武器：敵人持續扣血並跳 DOT
- 影系斗篷：玩家可閃避攻擊
- 水晶盾：玩家受擊後反傷
- 終局冠冕：玩家死亡時有機率復活
- 金幣 / 經驗 / 掉落詞綴：戰鬥結算數字有變化

## 設計提醒

不要再讓冒險、副本、塔各自寫一套裝備效果。

正確方向是：

1. 裝備資料只描述能力。
2. 共用解析器統一讀取能力。
3. 共用戰鬥核心統一觸發能力。
4. 各場景只負責把結果顯示出來。

這樣之後新增裝備、圖紙、套裝、Boss 獎勵時，才不會再發生「tooltip 有寫，但戰鬥沒反應」。
