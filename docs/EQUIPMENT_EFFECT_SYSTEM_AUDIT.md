# 裝備特效與詞綴觸發整理

本文件整理目前裝備 `specialEffects`、隨機詞綴 `affixBonuses`、強化詞條 `enhancementBonuses`、套裝效果與戰鬥核心的接線狀態。

目標不是只讓 tooltip 顯示漂亮，而是確保玩家看到的每一個特殊能力，都能在冒險、副本與後續塔戰鬥中以同一套規則觸發。

## 整體結論

目前裝備顯示系統已經能列出很多詞條，但戰鬥核心只完整接上部分效果。

已相對穩定：

- 攻擊、防禦、生命、爆擊率、爆擊傷害、攻擊速度
- 吸血
- 穿甲
- 火焰額外傷害

部分接上，但需要統一：

- 減傷
- 冰、雷、毒
- 套裝效果
- 塔戰鬥的舊吸血與減傷邏輯

尚未真正落地：

- 雙重打擊
- 處決
- 反傷
- 閃避
- 復活
- 生命恢復
- Boss 傷害
- 虛空傷害
- 金幣、經驗、掉落加成

## 建議架構

新增一個共用解析層，例如：

- `EquipmentEffectResolver`
- 或 `CombatEffectResolver`

它應該負責把所有裝備來源整理成同一份效果總表：

- 裝備基礎數值
- `specialEffects`
- `affixBonuses`
- `enhancementBonuses`
- `affixes[].stats`
- 套裝效果
- 戰術技能

戰鬥核心與獎勵結算都不應該自己去猜 item 上面有哪些欄位。

## 觸發階段

### 1. 常駐數值

這類效果只要裝備上就應該立刻反映在角色面板與戰鬥。

| 效果 | 鍵值 | 現況 | 備註 |
|---|---|---|---|
| 攻擊 | `atk`, `attack` | 已接上 | 由 `CharacterLogic.getTotalAtk()` 統一計算 |
| 防禦 | `def`, `defense` | 已接上 | 由 `CharacterLogic.getTotalDef()` 統一計算 |
| 生命 | `hp` | 已接上 | `maxHp` 會吃 `getAffixHpBonus()` |
| 爆擊率 | `critChance` | 已接上 | 由 `getCritChance()` 計算 |
| 爆擊傷害 | `critDamage` | 已接上 | 由 `getCritDamage()` 計算 |
| 攻擊速度 | `attackSpeed` | 已接上 | 由 `getAttackSpeed()` 計算 |
| 全屬性 | `allStats` | 部分接上 | 強化與套裝有接，`specialEffects` 裡的 `allStats` 需要統一解析 |

### 2. 攻擊命中時

這類效果在玩家攻擊命中後觸發。

| 效果 | 鍵值 | 現況 | 預期規則 |
|---|---|---|---|
| 吸血 | `lifesteal` | 已修正 | 造成傷害後，依傷害比例回血；早期低傷害至少回 1，滿血不觸發 |
| 火焰 | `fire` | 已接上 | 依比例追加傷害 |
| 冰 | `ice` | 半套 | 應降低敵人攻擊頻率數秒，目前核心只回傳 slow 資料 |
| 雷 | `thunder` | 半套且語意不一致 | 描述是暈眩，冒險場景目前卻顯示攻速提升，需要修正 |
| 毒 | `poison` | 半套 | 應套用 DOT 跳字，目前核心只回傳 poison 資料 |
| 雙重打擊 | `double_strike` | 未接上 | 擲機率後追加一次副傷害或再次攻擊 |
| 處決 | `execute` | 未接上 | 敵人低於指定 HP 門檻時追加傷害 |
| Boss 傷害 | `bossBonus` | 未接上 | 目標是 Boss 時提高玩家造成傷害 |
| 虛空傷害 | `voidDamage` | 未接上 | 建議作為無視部分防禦的額外傷害或特殊元素傷害 |
| 暈眩機率 | `stunChance` | 未接上 | 和 thunder 需要統一規則，避免兩種暈眩來源互相矛盾 |
| 緩速機率 | `slowChance` | 未接上 | 和 ice 需要統一規則 |

### 3. 玩家被攻擊時

這類效果在怪物攻擊玩家時觸發。

| 效果 | 鍵值 | 現況 | 預期規則 |
|---|---|---|---|
| 減傷 | `damageReduction` | 部分接上 | 角色邏輯有算詞綴與強化，但 `specialEffects` 需要統一接入 |
| 閃避 | `dodgeChance` | 未接上 | 擲機率成功時傷害歸零，顯示閃避 |
| 反傷 | `damage_reflect` | 未接上 | 受到傷害後，反彈部分實際傷害給怪物 |
| 復活 | `revive` | 未接上 | 死亡時擲機率，成功後回復一定生命 |

### 4. 戰鬥持續中

這類效果需要時間軸或戰鬥 tick。

| 效果 | 鍵值 | 現況 | 預期規則 |
|---|---|---|---|
| 生命恢復 | `hpRegen` | 未接上 | 每秒或每次攻擊節奏回復生命 |
| DOT 中毒 | `poison` | 半套 | 需要實際扣血、跳字、倒數圖示 |
| 緩速 / 暈眩 | `ice`, `thunder`, `slowChance`, `stunChance` | 半套 | 需要改變怪物攻擊排程或暫停攻擊 |

### 5. 戰鬥結算時

這類效果在戰鬥勝利、掉落與獎勵發放時觸發。

| 效果 | 鍵值 | 現況 | 預期規則 |
|---|---|---|---|
| 金幣加成 | `gold_bonus` | 未接上 | 戰鬥勝利時計算額外金幣 |
| 經驗加成 | `exp_bonus` | 未接上 | 戰鬥勝利時計算額外經驗 |
| 掉落加成 | `drop_bonus` | 未接上 | 掉落擲骰時增加機率或額外擲骰 |

## 目前資料中有出現的特效類型

以下是目前資料庫中實際出現的 `specialEffects` 類型：

| 類型 | 出現狀態 | 建議優先級 |
|---|---|---|
| `lifesteal` | 多件裝備使用 | 高，已修但需納入統一解析 |
| `damageReduction` | 多件防具、配方使用 | 高 |
| `armorPenetration` | 多件武器使用 | 高，已接但需統一 |
| `fire` | 多件武器、元素裝備使用 | 高，已接但需統一 |
| `ice` | 元素武器與配方使用 | 高 |
| `thunder` | 元素武器與配方使用 | 高 |
| `poison` | 毒系武器與配方使用 | 高 |
| `double_strike` | 狼牙、泰坦、虛空等武器使用 | 高 |
| `execute` | 巫妖、泰坦、惡魔系武器使用 | 高 |
| `dodgeChance` | 斗篷、影系防具、配方使用 | 中 |
| `damage_reflect` | 盾與重甲使用 | 中 |
| `critDamage` | 多件裝備使用 | 中，常駐數值應統一吃入 |
| `hp` | 防具與飾品使用 | 中，常駐數值應統一吃入 |
| `hpRegen` | 塔裝備與配方使用 | 中 |
| `revive` | 終局裝備使用 | 中 |
| `allStats` | 配方使用 | 中 |
| `voidDamage` | 虛空配方使用 | 中 |

## 實作順序建議

### 第一階段：統一讀取

建立共用解析器，先不改戰鬥表現，只把所有來源整理成同一份 bonus：

- `getEquipmentEffectTotals(character)`
- `getCombatEffectTotals(character)`
- `getRewardEffectTotals(character)`

完成後，`FightManager`、`CharacterLogic`、掉落結算都改吃這份總表。

### 第二階段：補齊戰鬥命中效果

優先處理玩家最容易感受到的攻擊效果：

- 雙重打擊
- 處決
- Boss 傷害
- 冰 / 雷 / 毒
- 虛空傷害

### 第三階段：補齊受擊效果

處理防禦型裝備存在感：

- 閃避
- 反傷
- 復活
- `specialEffects` 減傷

### 第四階段：補齊結算效果

最後處理經濟與收集成長：

- 金幣加成
- 經驗加成
- 掉落加成

## 驗收標準

每個效果都需要至少有一個自動驗證案例：

- 裝備該效果
- 進行一次攻擊、受擊、戰鬥 tick 或結算
- 檢查 HP、傷害、狀態、獎勵是否符合預期

最低測試清單：

- 史萊姆之劍：命中後吸血
- 狼牙刀：雙重打擊會追加傷害
- 泰坦之錘：低血敵人受到處決加成
- 冰系武器：敵人攻擊頻率降低
- 雷系武器：敵人被暈眩
- 毒系武器：敵人持續扣血並跳 DOT
- 影系斗篷：玩家可閃避攻擊
- 水晶盾：玩家受擊後反傷
- 終局冠冕：玩家死亡時有機率復活
- 金幣 / 經驗 / 掉落詞綴：戰鬥結算數字有變化

## 設計提醒

不要再讓冒險、副本、塔各自寫一套裝備效果。

正確方向是：

1. 裝備資料只描述能力。
2. 共用解析器統一讀取能力。
3. 共用戰鬥核心統一觸發能力。
4. 各場景只負責把結果顯示出來。

這樣之後新增裝備、圖紙、套裝、Boss 獎勵時，才不會再發生「tooltip 有寫，但戰鬥沒反應」。
