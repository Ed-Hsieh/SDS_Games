# 旅人手札與地圖事件設計

這份文件把「旅人手札」與「地圖事件」收斂成同一套設計方向。目標不是增加更多提示，而是讓玩家覺得自己正在閱讀、推理、做準備，並在探索中碰到有意義的世界反應。

## 核心方向

旅人手札是玩家的腦袋。

它不應該像系統任務列表，不應該在上方常駐告訴玩家下一步，也不應該把所有東西都叫線索。它應該把玩家已經聽見、看見、做過、還沒確認的內容整理成可回讀的紀錄。

地圖事件是世界對玩家的回應。

事件不應該只是「走到問號，抽一個結果」。它應該帶來資源、風險、情報、支線入口、地點記憶或章節壓力。玩家看到事件時，應該期待它可能幫助這趟探索，也可能把世界的某一面打開。

## 名詞切分

目前最大的語意問題是「線索」被拿來指太多東西。後續 UI 與資料應固定使用以下分類：

| 分類 | 定義 | 出現位置 | 玩家感受 |
| --- | --- | --- | --- |
| 委託 | NPC、公佈欄或事件交給玩家處理的事情 | 旅人手札 / 委託頁 | 有人需要我幫忙 |
| 首領痕跡 | BOSS 流程中的證據、推進條件、最終觸發方式 | 旅人手札 / 痕跡頁；冒險地圖快捷入口 | 我正在追某個危險存在 |
| 見聞 | 地圖事件、地標、世界碎片、短篇故事記錄 | 旅人手札 / 見聞頁 | 世界不只是戰鬥 |
| 鍛造備忘 | 缺少材料、圖紙來源、裝備路線 | 旅人手札 / 備忘頁或鍛造頁內 | 我知道怎麼準備下一步 |
| 城鎮記憶 | 完成支線後留下的人物、地點、狀態變化 | 旅人手札 / 人物與城鎮頁 | 我做過的事留在世界裡 |

避免使用：

- 大廳叫線索、冒險叫線索，但意思不同。
- 「下一步」直接寫在上方 UI。
- 任務目標用純系統語言，例如「史萊姆 0/5」單獨出現。

推薦用語：

- 「書記請我確認農田邊史萊姆異常，至少消滅 5 個靠近南門的史萊姆。」
- 「我現在是否可以去南門外確認？」
- 「這段痕跡還差一個能把銀絲引回伏道的東西。」

## 旅人手札資訊架構

旅人手札建議拆成五個頁籤，但第一版可以先做前三個：

| 頁籤 | 第一版必要性 | 內容 |
| --- | --- | --- |
| 委託 | 必做 | 主線、支線、懸賞、副本任務。按章節與狀態排序。 |
| 痕跡 | 必做 | BOSS 追蹤流程。只顯示已發現痕跡，不預告未知條件。 |
| 見聞 | 必做 | 地圖事件、地標、短篇片段。可作為收藏與世界理解。 |
| 備忘 | 第二輪 | 圖紙、缺料、裝備路線。從鍛造頁同步，不常駐打擾玩家。 |
| 城鎮 | 第二輪 | NPC 後日談、城鎮狀態、已完成支線的結果。 |

### 委託頁

委託頁應像一份筆記，不像任務表。

卡片只放：

- 委託名
- 來源人物或物件
- 篇章
- 狀態
- 一句目前摘要

右側詳細：

- 來源：誰說的，在哪裡聽見。
- 目前紀錄：一句故事化摘要。
- 我在想：用內心提問提示玩家方向。
- 補齊紀錄：目標進度，但用敘事句包裝。
- 回報對象：只在完成後顯示，不在手札裡直接回報。

狀態語氣：

| 狀態 | 顯示語氣 |
| --- | --- |
| 可收入 | 「這還只是聽聞。」 |
| 紀錄中 | 「手札還有空白。」 |
| 可回報 | 「事情已經有結果，該找當事人說清楚。」 |
| 已歸檔 | 「這件事告一段落，但變化留在城鎮裡。」 |

### 痕跡頁

痕跡頁只處理 BOSS。

它不應該叫委託，因為 BOSS 流程可能來自怪物痕跡、地標、道具、謎題、交易或伏擊。

顯示規則：

- 不顯示未知總數，不寫 `0/4`。
- 已發現內容依序顯示為「痕跡一、痕跡二、痕跡三」。
- 每條痕跡要有來源：地點、怪物、NPC、道具或事件。
- 最終觸發方式只在玩家已經湊齊條件後顯示。
- 如果還沒湊齊，只給玩家可推理的內心提問。

範例：

> 痕跡二：斷裂誘餌鉤  
> 鍛造師說切口太乾淨，普通野獸做不到。  
> 我現在是否該找一個能把牠引回伏道的東西？

### 見聞頁

見聞頁承接地圖事件，不強迫玩家做任務。

事件如果只是資源事件，不一定要永久入冊；但以下事件應入冊：

- 第一次遇見的章節事件。
- 解鎖支線的事件。
- 解釋地脈、古龍、魔王、城鎮狀態的事件。
- 完成後會改變城鎮或地點描述的事件。

見聞不是任務，因此不應有回報按鈕。它可以顯示：

- 發現時間或章節。
- 發現地點。
- 當時選擇。
- 留下的後果。

## 地圖事件設計

事件要有期待感，但不能破壞 RPG 平衡。每個事件都應該至少符合一種用途：

| 事件角色 | 玩家期待 | 風險控制 |
| --- | --- | --- |
| 補給 | 回血、藥水、低階素材、營地安全感 | 回報低，主要是延長探索 |
| 交易 | 花金幣換情報、材料、誘餌、地圖工具 | 價格與章節掛鉤，不給強裝 |
| 風險回報 | 受傷、失金幣、詛咒，換較高收益 | 要有清楚意圖，不做純懲罰 |
| 支線種子 | 解鎖人物短篇或特殊委託 | 一次性，解完後不重複出現 |
| 世界見聞 | 補主線沒說完的世界側面 | 低收益，主要給故事與推理 |
| 章節壓力 | 第三章熱風、深淵、避難者、耐久壓力 | 不該隨機秒殺，只製造準備需求 |
| 首領痕跡 | 推進 BOSS 流程 | 必須綁地點、怪物或條件，不可全圖亂出 |

### 事件不重複規則

目前玩家感覺重複，是因為事件缺少記憶與替代狀態。建議資料層加入：

```js
{
  repeatPolicy: 'repeatable' | 'one_time' | 'chapter_once' | 'until_resolved',
  memoryKey: 'event.field_notice_board',
  cooldownSteps: 12,
  resolvedFallback: '你又看見那塊公告欄，但上面已沒有新的紙。'
}
```

規則：

- `story_seed`、`side_story` 預設 `one_time`。
- `world_lore` 預設 `chapter_once` 或 `until_resolved`。
- `resource` 可重複，但要有冷卻。
- 同一事件短時間不可連續抽到。
- 已解完的事件如果再次碰到，只用右側動態一句帶過，不再彈出完整選擇。

### 事件與地點綁定

事件應該分成「區域池」與「地點池」。

區域池：

- 適合一般補給、交易、風險回報。
- 例如南門外近郊可遇到巡路小龕、採集袋、迷路商人。

地點池：

- 適合支線種子、首領痕跡、世界見聞。
- 例如獵人棧道才會出現銀絲絆線、斷裂誘餌鉤、舊營火警告。

資料建議：

```js
{
  id: 'hunter_tripwire_cache',
  eventRole: 'boss_trace',
  zones: ['low'],
  landmarkTags: ['hunter_trail', 'silver_thread_route'],
  chapterRange: [1, 1],
  requires: { quest: 'main_003' },
  repeatPolicy: 'until_resolved'
}
```

### 章節權重

| 章節 | 補給 | 交易 | 風險回報 | 支線種子 | 世界見聞 | 章節壓力 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 第一章 | 高 | 中 | 低 | 中 | 中 | 低 |
| 第二章 | 中 | 中 | 中 | 高 | 高 | 中 |
| 第三章 | 低 | 中 | 高 | 中 | 高 | 高 |

設計目的：

- 第一章讓玩家學會探索，不要太常被事件懲罰。
- 第二章讓支線與世界見聞打開深度。
- 第三章讓事件開始反映終局壓力，但仍不能讓玩家覺得隨機被處罰。

## 支線與事件連動

支線不應全部由 NPC 直接發任務。比較好的節奏是：

1. NPC 提到一件怪事。
2. 玩家在地圖碰到相關事件或物件。
3. 旅人手札出現見聞或委託。
4. 玩家帶著發現回到相關人物。
5. 支線進一步展開，並留下城鎮或地點狀態。

### 第一章切片

| 支線 | 事件/地點入口 | 手札分類 | 狀態變化 |
| --- | --- | --- | --- |
| 南門守衛的靴底 | 南門巡邏痕跡、獸皮掉落 | 委託 | 南門描述更可信 |
| 藥師的空瓶 | 農田史萊姆、凝膠樣本 | 委託 | 藥水供應合理化 |
| 鐵匠的煙囪 | 鍛造鋪白煙、鐵礦石 | 委託 | 鍛造功能更像戰備 |

### 第二章切片

| 支線 | 事件/地點入口 | 手札分類 | 狀態變化 |
| --- | --- | --- | --- |
| 採藥籃不會說謊 | 毒霧林地、荊棘籃 | 委託 + 見聞 | 藥師理解女巫交易 |
| 沉鐘下的失眠人 | 城鎮夜聲、回聲殼 | 見聞 → 委託 | 書記記錄沉鐘節奏 |
| 墓園書籤 | 遠古墓道、骨片、書籤 | 見聞 → 委託 | 巫妖曾有名字 |
| 帳冊上的名字 | 影徽、灰燼帳冊頁 | 委託 | 公告欄出現失蹤名單 |
| 黑市收藏家的標籤 | 詛咒碎片、黑市暗號 | 見聞 → 交易 | 黑市變情報來源 |

### 第三章切片

| 支線 | 事件/地點入口 | 手札分類 | 狀態變化 |
| --- | --- | --- | --- |
| 北境來信 | 城門信使、飛龍鱗 | 見聞 → 委託 | 城鎮開始接收北境消息 |
| 最後一鍋湯 | 避難者廚房、補給路線 | 委託 | 城鎮不只恐慌，也有生活 |
| 秘銀不是傳說 | 逃匠筆記、秘銀礦石 | 鍛造備忘 + 委託 | 終局裝備路線合理化 |
| 書記的最後索引 | 黑印、索引封皮 | 城鎮記憶 | 手札從工具變成記憶 |

## UI 設計原則

### 旅人手札

- 不要在列表卡片塞滿資訊。
- 左側只做搜尋、分類、狀態。
- 右側顯示目前選中的故事。
- 詳情內才顯示進度與玩家思考。
- 可回報的任務不在手札中完成，只顯示「該找誰」。

### 事件彈窗

事件彈窗應該像短篇場景，不像系統抽卡。

結構：

- 標題：地點或事件名。
- 一段短描述。
- 選項，每個選項有一句意圖。
- 結果不只列數字，要先有敘事，再顯示獲得/損失。

按鈕範例：

```text
整理供桌
穩定恢復，適合繼續探索。
```

避免：

```text
回血 +30%，防禦 +5，持續 10 秒
```

數值可以顯示，但應放在結果區或小字，不要搶走事件閱讀感。

### 右側動態

右側動態應是旅途摘要，不複製對話原文。

好的訊息：

- 「你把村長提到的南門路線收入手札。書記正在等你把城外異常整理成第一頁紀錄。」
- 「你在獵人棧道看見被割斷的誘餌鉤。這不像普通野獸留下的痕跡。」
- 「藥師看完凝膠樣本後沉默了一會兒，基礎藥水供應開始穩定。」

不好的訊息：

- 直接重複 NPC 對話。
- 純系統文字：「任務已更新」。
- 一直提醒「請查看線索簿」。

## 第一輪實作切片

第一輪不要大改所有系統，先做最能改善體驗的切片：

1. UI 文案分流
   - 大廳手札入口叫「旅人手札」。
   - 委託頁不要叫線索。
   - 冒險 BOSS 追蹤叫「首領痕跡」或「痕跡簿」。

2. 事件記憶
   - 為 `story_seed`、`side_story`、`world_lore` 加 `repeatPolicy`。
   - 已觸發的事件不再完整彈出。
   - 已解完事件改成右側動態一句帶過。

3. 手札詳情改寫
   - 卡片少放數字。
   - 詳情的「我在想」依任務類型生成：找人、探索、擊殺、收集、鍛造、回報。
   - 進度文字改成敘事句，數字縮到旁邊。

4. 地點池
   - 銀鐮伏獵者相關痕跡只在獵人棧道、舊營火、銀絲伏道附近出現。
   - 血月角鹿痕跡只在古樹守衛後，月苔坡、溪谷交界、折角路線附近出現。
   - 第二章支線種子只在對應章節與地點出現。

5. 動態訊息整理
   - 對話完成後只寫狀態摘要。
   - 事件完成後寫「你注意到什麼 / 誰因此改變」。
   - 不把完整對話塞進動態。

## 驗收標準

完成後，玩家應能回答：

1. 我現在手札裡有哪些委託？
2. 哪些是 BOSS 痕跡，而不是委託？
3. 我在地圖上碰到的事件為什麼會出現在這裡？
4. 這個事件是補給、交易、風險、支線、見聞還是章節壓力？
5. 我完成一條支線後，哪個人物、地點或城鎮狀態改變了？
6. 我不看上方提示，也知道可以去哪裡自己確認下一步。

如果玩家覺得「我只是在清任務」，設計就失敗。  
如果玩家覺得「我在把一個逐漸壞掉的世界記下來，並且我的行動會留下痕跡」，設計就成立。
