# UI And Art Guide

更新日期：2026-07-03

這份文件整理 UI 與美術規格；後續介面、圖片、Icon、場景互動以這裡為準。

## UI 原則

- 維持原有版面中有效的結構，做套皮與資訊密度精修。
- 小幅度重構時，要移除不好的舊 CSS、舊元件與舊文案，再建立新設計。
- 不要在舊介面上繼續堆新的方框，避免疊床架屋。
- 桌面優先，不再打磨手機版本。
- 主要驗收尺寸：`1280x631`。
- 不允許橫向卷軸。
- Icon 尺寸要全域固定，避免在鍛造、手札、百科、物品卡中忽大忽小。
- Scroll bar 要有全域樣式，不讓瀏覽器預設樣式破壞畫面。
- 上方已有 TAB 時，下方內容不要再重複一個同語意的區塊。
- 內容區要依功能特性設計，不套同一個模板到委託、百科、鍛造、角色、倉庫。

## 目前 UI 重點

- 旅行行囊：角色、背包、倉庫需要重新整理資訊密度與分類。
- 角色 TAB：套裝資訊要乾淨呈現，未穿戴裝備灰階，套裝 BUFF icon 顯示啟用效果。
- 裝備詳細：左右版面。左側是基礎數據，右側是效果與 BUFF 類型；沒有 BUFF 時也保留版面穩定。
- 鍛造：製作頁目前可作為資訊密度參考；強化、修復、詞綴重鑄要重構到同等品質。
- 戰鬥面板：圓形主副手節奏、狀態區、裝備效果與怪物資訊要重新排版。
- 戰利品結算：背包與戰利品欄位不能擠壓，scroll 與 item card 要符合遊戲樣式。
- 系統設定：音效設定在系統第二層，不使用大廳右下角音效按鈕，不做 popup。

## 百科 UI

百科上方保留五大分類按鈕：裝備、素材、圖紙、物品、怪物。五個分類要維持同一行，不產生橫向卷軸；如果寬度不足，優先壓縮按鈕寬度與文字間距，而不是擠壓下方列表。

- 左側條目不要有 hover 動畫影響閱讀。
- 未解鎖物品顯示問號，不顯示原圖。
- 編號只做排序，不刻意顯示在百科上。
- 來源要支援怪物 icon 或問號，並能快速連結到百科。
- 圖紙成品使用 icon 與快速連結，不把完整裝備數值塞到卡片內爆版。
- 物品頁要重新定義用途與來源，不沿用裝備模板。
- 怪物頁顯示怪物圖、等級、出沒地、掉落物與狀態效果；不要沿用物品或裝備模板。

## 美術方向

- 主線 BOSS 現行滿版大圖風格保留。
- 非主線 BOSS 與菁英怪物可以有場景粉飾，但不要比主線 BOSS 更華麗。
- 普通小怪可以沒有背景。
- 圖紙圖片應維持羊皮紙、夾具、暗色背景、設計稿線條的既有風格；不要用 CSS 裁切修補歪斜，優先重新生成。
- UI 外框與套皮可以重複使用同一張素材以節省效能。
- 生成圖片內不要放文字、UI 框線或按鈕狀資訊，避免與遊戲 UI 疊加。
- 圖片應放進設計好的方框中；方框由 UI 控制，圖片專注於內容或質感。

## 場景互動方向

完整走入式場景互動延後到後期打磨。

目標方向：

- 場景圖上有攤位、建築或物件熱點。
- 滑鼠移到可互動物件時出現反光。
- 點擊後聚焦到該攤位或 NPC。
- 再開啟較大的 NPC 對話、交易或功能介面。

市集邊棚與賭場未來都應朝這個方向，而不是用大量 TAB 把 NPC 擠在一個畫面。

## 資產流程

- 新圖片放在 `src/assets/images/art-v2/` 相關分類底下。
- 新資產要接進 `src/utils/AssetManifest.js`。
- 替換圖片後要檢查百科、裝備卡、鍛造、戰鬥與場景引用。
- 裁切 sheet 時要保持角色、物品或圖紙置中，不用 CSS 補救歪斜。
- 需要驗證資產覆蓋時執行 `node scripts/AssetCoverageCheck.mjs`。

## 驗收清單

- `1280x631` 下沒有橫向卷軸。
- 圖片、icon、素材、詞綴與套裝不爆版。
- 物品詳細、鍛造、百科、旅人手札、旅行行囊、戰鬥、戰利品都能在小版面中維持資訊密度。
- 同一類 UI 不保留互相打架的舊 CSS。
- 使用者能從非戰鬥介面先理解裝備效果，再在戰鬥中看到對應 icon 或狀態。
